# Nitrobowl

Rocket-powered car soccer in the browser. Drive, boost, fly, and hit a very large ball
into a very large goal.

TypeScript + Three.js, no framework, no asset files — every mesh, texture and sound in the
game is generated at runtime. The physics is a purpose-built deterministic 120 Hz
simulation rather than a general-purpose engine; the reasoning and all the tuned numbers
are in **[DESIGN.md](DESIGN.md)**.

```bash
npm install
npm run dev        # http://localhost:5173
```

| Script | What it does |
| --- | --- |
| `npm run dev` | Vite dev server with hot reload |
| `npm run build` | Type-check, then bundle to `dist/` |
| `npm run preview` | Serve the production build |
| `npm test` | Run the physics and rules test suite |
| `npm run typecheck` | Type-check only |

Needs a browser with WebGL 2.

## Controls

Keys are rebindable in **Controls** from the main menu or the pause screen. Defaults:

| | Keyboard | Gamepad |
| --- | --- | --- |
| Accelerate | `W` | Right trigger |
| Reverse / brake | `S` | Left trigger |
| Steer | `A` / `D` | Left stick |
| Jump / flip | `Space` | A |
| Boost | `Left Shift` or right click | B / RB |
| Powerslide | `Left Ctrl` or left click | X / LB |
| Air roll (hold) | `Left Alt` | X |
| Air roll left / right | `Q` / `E` | — |
| Ball cam | `C` | — |
| Pause | `Esc` | — |
| Debug overlay | `F3` | — |

**Airborne, the controls change meaning.** `W`/`S` become pitch and `A`/`D` become yaw.
Hold air roll and `A`/`D` become roll instead. This context switch is deliberate and is
what makes aerial control workable from a keyboard.

## How to actually play

- **Jump, then press jump again with a direction held** to flip. Forward for a front
  flip, back for a backflip, sideways for a side flip. With no direction held you get a
  flat double jump instead, which gets you higher.
- **Flip into your landing** to convert the flip's impulse into ground speed. That is a
  *wavedash*, and it puts you well past the 1410 uu/s throttle ceiling without spending
  boost. Nothing in the code special-cases it — it falls out of the physics.
- **Powerslide is not a drift boost.** It breaks lateral grip so you can rotate tighter
  than the turn-radius curve allows, while keeping most of your speed. Use it to snap the
  car around, then release and re-grip.
- **Drive up the walls.** The floor, walls and ceiling meet in continuous curves with no
  sharp corners anywhere, so at speed you can run floor → wall → ceiling in one line. Lose
  speed and you slide back down.
- **Boost is a resource.** You start every kickoff with 33 and burn 33.3 per second. The
  six big pads on the outside fill the tank but take 10 seconds to come back and cost you
  field position; the 28 small pads give 12 each and refresh in 4, and they line up so you
  can refill on the way back to defence.
- **Supersonic** is 2200 uu/s. Hit a car front-on at that speed and you demolish it — it
  respawns near its own goal three seconds later.

## Project structure

```
src/
  core/       constants (every tuned number), vec3/mat3 math, input + bindings
  physics/    field SDF, car controller, ball, OBB collision, world stepper
  entities/   car and ball render objects
  scenes/     arena construction, palette, particle pool
  ai/         bot state machine, three difficulty tiers
  ui/         HUD, menus, debug overlay, styles
  audio/      Web Audio synthesis
  game/       match rules, chase camera, orchestration
tests/        69 tests over the physics and rules
DESIGN.md     the research the whole thing is built on
```

Three things are worth knowing before reading the code:

**The simulation runs at a fixed 120 Hz** in Unreal Units (1 uu = 1 cm), driven by an
accumulator. Jump-hold windows and dodge timers are specified in ticks and only reproduce
correctly at that rate. Rendering is decoupled and draws whatever the latest tick
produced.

**The arena is an analytic signed distance field**, not a mesh — the interior is a convex
intersection of ten half-spaces with cylindrical fillets on every edge and spherical ones
on every corner. Contacts, normals and wheel raycasts are all closed-form. The *visual*
shell is then generated by projecting a subdivided cube onto that same field, so the
geometry you see is exactly the geometry you hit.

**Cars collide through a box hitbox, not their visual mesh.** The wheels stick out past
it and the nose is shorter than it. That mismatch is not a bug — it is central to how the
genre feels, and it is why a touch off a wheel sometimes sends the ball somewhere the
contact geometry does not justify.

## Tests

```bash
npm test
```

The suite pins behaviour to the researched figures rather than to whatever the code
currently does: the 1410 uu/s throttle ceiling, 3500 uu/s² braking, the turn-radius table,
a 3.1 s full-lock circle, flip directions and impulse magnitudes, roll-over-pitch-over-yaw
air authority, and restitution-squared bounce height.

`tests/mechanics.test.ts` is the interesting one. It tests techniques that are *emergent*
— wall and ceiling driving, wavedashing, half-flips, flip resets — none of which have any
supporting code. They work only if the underlying constants are right, so they break
before subtler regressions become visible.

## Originality

This is an original game inspired by the rocket-league-car-soccer genre. Game mechanics
and physics behaviour are not copyrightable, and the simulation model here is
deliberately tuned to match published community measurements of how that genre plays —
those figures are cited in DESIGN.md.

Everything else is this project's own work. There are no third-party names, logos, car
names or branding; no extracted, ripped or derived art, audio, meshes or textures; and no
asset files of any kind. Meshes are built from primitives in code, textures are drawn to
a canvas at load, and every sound is synthesised with the Web Audio API. The arena, cars,
palette, HUD and naming are original.
